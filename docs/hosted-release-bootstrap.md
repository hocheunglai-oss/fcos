# Qualification before the consolidation PR merges

The temporary bootstrap lets the actual hosted controller qualify while all repairs remain on one draft PR. It is a one-time setup path, never a second Production release path. The normal caller and Production coordinator admission remain restricted to protected `main`.

## Immutable source binding

1. Review and publish the complete controller commit `C` on the consolidation PR. Do not merge it yet.
2. Render `.github/qualification/hosted-release-bootstrap.yml`, replacing all five `__FCOS_CONTROLLER_SHA__` occurrences with `C`. Put only that reviewed rendered file at `.github/workflows/authenticated-release.yml` on a dedicated `codex/hosted-qualification-…` branch based on `C`. Commit this bootstrap as `B`. The existing default-branch workflow supplies GitHub's registered dispatch entrypoint; the protected branch supplies the exact caller. Do not overwrite the default-branch file.
3. Before publishing the branch, suppress its automatic Vercel deployments. Apply and verify its exact protected-source restrictions, environment branch admission and operator identity under the existing setup/write controls. The candidate, controller and bootstrap may be different commits; record each explicitly. Neither an ordinary PR branch nor a mutable branch head is trusted controller authority.
4. Admit the public five-field `qualificationSource` in the release setup: `{ref,bootstrapSha,callerWorkflowRef,controllerSha,candidateSha}`. `callerWorkflowRef` is `hocheunglai-oss/fcos/.github/workflows/authenticated-release.yml@<ref>`. Bind the separately reviewed coordinator `qualificationAdmission` to this tuple, numeric repository ID, caller workflow SHA, exact reusable workflow identity and setup hash. Set `FCOS_HOSTED_QUALIFICATION_ADMITTED=true` only for this admitted tuple. These are one-time administrator decisions, not self-admission by the candidate.

The early manifest entrypoint checks the actual protected branch, run, operator, caller and reusable controller before checking out the candidate or exposing provider observation credentials. Its GitHub read-only credential needs repository Contents, Actions and Administration/protection reads; verify that permission during setup. Store `FCOS_HOSTED_GITHUB_READ_TOKEN` as a repository secret: the caller passes only this explicitly declared metadata secret to the reusable controller so environment-free prepare/publisher jobs can inspect protection. Do not use `secrets: inherit`; candidate execution receives no secret expression or credential environment. Provider credentials remain in their separate protected environments. Both manifest stage and execution mode must be `qualification`. The coordinator independently authenticates OIDC and the admitted tuple on every bootstrap request, deriving a qualification-only principal. It refreshes live source metadata at registration and `begin`/`claim` boundaries. Journal-only operations retain the immutable binding without repeating those reads; this permits readback of an original uncertain submission even after branch drift. New admissions still fail on drift. It rejects registration for another candidate/setup, Production approval/resume, Production writes, financial access and bootstrap use after epoch activation.

## Hosted setup and qualification sequence

Publish the credential-free check image with the bootstrap's `toolchain` phase and the [one-time toolchain contract](hosted-release-toolchain.md), retaining the existing coordination lease through registry readback. The workflow's built-in GitHub token provides registry permission; do not expand a personal token to make this work. Bind the verified image digest into the setup before qualification. Then disable toolchain publication and fence it with all other legacy writers.

Provision the isolated coordinator host, its coordination-only database role, read-only metadata credential and dedicated hosted verification/Preview credentials. Apply the reviewed migration to the pinned database. Keep Production credentials out of the bootstrap environments. Import the original dependency evidence and permanent legacy fences using the [cutover procedure](hosted-release-cutover.md). Install the single epoch in qualification mode only after every old writer is fenced and all unresolved submissions are recorded. Unknown imported outcomes block new writes until definitive readback.

Dispatch the existing registered workflow on the exact protected bootstrap ref with `bootstrap_phase: qualification`, the admitted candidate and a qualification plan. It runs the real Preview deployment, candidate isolation, deterministic/database/browser checks, immutable publisher and validator, followed by the three journaled simulated Production boundaries. Exercise interruption and lost-response recovery by dispatching the same saved manifest in a new first-attempt run. Do not mint a new manifest or operation to escape an unknown outcome. A repair changes the controller/source admission and remains on the consolidation PR; historical evidence and consumed operations retain their original bindings.

Accept qualification only from actual hosted artifacts and coordinator readback. Verify the operator's actual iPhone notification receipt. Then finish the existing exact-source PR checks and merge the same consolidation PR. Admit the normal main caller, activate the same epoch, and remove only the qualified obsolete intermediate reviewer gates. Disable the temporary qualification flag/branch admission. Production still requires one final protected approval for each immutable deployment manifest.

This sequence neither approves the compatibility release nor combines it with the final application release. The frozen candidate, required Production observation and separately admitted status/supplier scopes remain unchanged.
