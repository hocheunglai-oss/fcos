# FCOS 2.0.289 application audit and fixes

The audit uses the verified Production source `f3472492ff4d0b0c70248a3c8e5c0012981a94b3` (2.0.288). Changes are isolated from the unfinished primary checkout.

## Corrected behavior

- Buyer-side variable-charge confirmation rejects every extra-cost update outside the selected supplier before reserving an operation or writing to Salesforce. The writer independently enforces the same scope. The reviewed legacy whole-case workflow remains explicit.
- Both notification endpoints resolve current Markets permissions on the server. Request-supplied capabilities cannot grant visibility or permission to change alert state. Preview mutation and governed CI restrictions remain effective.
- Marking notifications read retains the selected source and state. Overlapping loads discard obsolete responses; notification actions serialize, and filter changes require current-view readback. Bursts of quiet refresh events share one pending load.
- Unreadable API responses produce an error or cancellation rather than a successful empty result. Uncertain mutation responses invalidate prior browser snapshots before readback. Account changes reject old responses.
- Hedge Desk preserves the newest valid snapshot across overlapping refreshes, old background callbacks and cancellation. A failed refresh retains existing data and reports the error.
- The local runtime-cache fallback bounds retained JSON to 16 MiB and 64 entries, evicting the least recently used entry. Cache keys, access scopes, TTLs, invalidation, remote Vercel caching and verified Salesforce freshness retain their existing behavior.
- The lint toolchain pins patched brace-expansion 1.1.21 and js-yaml 4.3.2. The lockfile changes only these two existing development packages; the dependency audit reports zero vulnerabilities.
- Notification read/state actions share one guarded mutation path; repeated network response metadata and notification badge styles are consolidated without changing displayed colors or increasing the JavaScript budget.

## Verification and scope

The app-wide Node suite passed 4,529 tests with 41 skips and zero failures across 4,570 cases. The skipped database/concurrency tests require the disposable CI database; they remain release requirements. Lint, both type checks, compatibility registry and Graph-only source checks passed.

Actual-source regression fixtures cover supplier A/B authorization, dedicated notification authentication and service dispatch, malformed/cancelled responses, uncertain save outcomes at both fetch and body-read phases, account isolation, cache bounds and Hedge Desk entity response behavior. Four desktop browser tests failed against the original Production component/hook source and pass against the fixes. A fifth test covers incident verification completing after a filter change. They cover slow filter responses, source/state preservation, burst coalescing, mutation serialization, filter round trips, snapshot ordering, cancellation and unmount cleanup. Provider calls are stubbed in these fixtures.

The representative cache workload used 1,000 distinct 128-KiB values and no provider calls. Before: 1,000 retained entries / 125 MiB payload / 29.2 ms writes. After: 64 entries / 8 MiB payload / 108.6 ms writes. This reduces retained payload by 93.6%; it is a memory bound, with measurable serialization overhead, rather than a claim of faster remote requests. Ten simultaneous notification change events now create one request while the same view is loading.
