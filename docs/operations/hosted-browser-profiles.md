The hosted normal browser adapter selects its verifier from the admitted source
profile before private browser work. `prepare`, `reconcile` and deterministic
checks compile the same harness, activation-variable and15-module catalogue
composition before opening a hosted session. This is a pure source check, not a
new approval or external gate.

The supported compositions are:

| Candidate/profile | Real verifier | Xero business read |
| --- | --- | --- |
| Exact `be6daf6162480ca77ec8d4f04fe5aaa5b228a22c` / `compat_runtime_ordinary_admission_20261025` | Exact hosted ordinary compatibility adapter | `xeroPortalReceiptsList` and Receipt audit |

The ordinary adapter compares the full known candidate tuple with the existing
`ORDINARY_ADMISSION_DEPENDENCY_CONTEXT`: SHA, profile, source, lock, configuration,
Salesforce source, source-input digest and branch. It also requires the current
controller/manifest-bound source receipt, protected repository context and
read-only runtime. A SHA prefix, ambient enable variable or arbitrary boolean
does not enroll another candidate. The historical public compatibility entrypoint
still rejects be6; its old candidate guard is unchanged.

After provider/version/source/runtime checks and a fresh dedicated FCUNO login,
the adapter verifies the expected active non-CI role and all15 module permissions.
It removes ambient harness-enable flags and applies only the selected activation
variable to that private harness invocation. The workflow does not globally enable
either standalone normal verifier. Existing session import remains forbidden.

The ordinary path reuses the existing complete compatibility engine: real module
data, headings and workflow reads, initialized workspace preferences, same-context
background-sync Web Lock, telemetry exclusion, request classification, observer
settlement and confirmed cleanup. Its receipts read is the existing database
workflow, not an Accounting API or financial mutation. Missing data, denied reads,
late errors, unknown APIs, token refresh and writes still fail verification.

Normal evidence identifies its browser profile and includes compatibility
isolation where required. The publisher checks that same profile/catalogue contract
against the manifest and exact Preview. It keeps the producer's original time.
An uploaded failed report is diagnostic; it cannot become a passing check.

Failures retain fixed browser stages and codes. Compatibility diagnostics contain
only reviewed stage/reason/module/handler/category enums and bounded HTTP status.
No raw exception, response, URL query, credential, cookie or browser state is
published. A submit timeout with no observed authentication response emits
`AUTH_CONTEXT_RESPONSE_NOT_OBSERVED`; it does not establish invalid credentials.
A click timeout after an observed response retains the generic submit boundary. Both browser phases upload their redacted
report when the browser step ran, including on failure.

Known typed login failures also retain a closed `runtimeLoginObservation` block:
whether the single Login click completed, whether the exact same-origin
`POST /api/functions/authContext` request and response were observed, and its
actual HTTP status (or `null` when unknown). Passive main-frame navigation
observations retain only `candidate_login`, `candidate_callback`, `candidate_app`,
`issuer_login` or `other`, plus the final class. The callback class means the
candidate `/login` route has `federated=1`; its URL and parameters are not saved.
Milestones contain unique observed classes, not a complete redirect trace.

These observations add no request, click, login, retry or DOM/body read. False
means not observed; it does not establish that an event never happened. No
generic form-error category is emitted because there is no reviewed issuer
error selector. Raw URLs, query/fragment values, exception text, headers, bodies,
credentials and state stay private. The report and CLI summary accept only the
closed fields on known typed login failures; existing identity, origin, callback,
cleanup and freshness requirements remain mandatory.

The maintained CLI browser path validates the already-bound `runtime_parity`
proof and supplies its saved runtime to both the outer adapter and selected
harness. Keep this path for a retained Preview: do not call the standalone
verifier's default runtime collector, which would submit another runtime probe.
Original freshness/deployment/source constraints continue to apply; do not reset
timestamps or relabel expired/historical evidence as current.

These source changes do not authorize a workflow rerun, another Preview/probe,
cross-controller proof adoption or Production. A repaired controller is new source.
Continuation and any retained-Preview admission must separately bind that source
and preserve the journal. Compatibility and application Production stages remain
separate decisions.

Focused validation uses `tests/hosted-browser-composition.test.js`. Its joined
workflow-shaped environment has no harness-enable flags and executes the real
FCUNO login logic, selected verifier, isolation engine and publisher validation
with hermetic native/provider IO. It is not actual hosted authentication or a
Production proof.

The be6 ordinary catalogue follows its actual components and request contracts:
the public Market price board uses `marketPulseSnapshot`; Open Collections uses
the bounded `salesforceBuyerInvoicesDue` read; Incoming Payments uses the rendered
page-copy heading. Exception Review checks the scanned universe separately from
the classified exception rows, including its explicit empty state. Hedge Desk
matches the exact snapshot request separately from its mandatory AppConfig read.
Successful unrelated responses cannot replace a required response, and a failed
required response remains fatal. Legitimate unavailable financial calculations
or negative amounts do not become page-load failures merely because of their
text or styling.

The current application verifier shares these business-surface contracts while
keeping its distinct saved Xero integrity report and workflow checks. It does not
enroll another SHA in the exact be6 compatibility profile. Same-context background
isolation, telemetry exclusion, denied-request handling and complete response
settlement remain part of verification, including late failures during cleanup.

Source-archive Preview deployments use detached HEAD, so historical branch-only
settings do not supply Microsoft Graph identities to a new Preview. The reviewed
`verification.publicPreviewRuntimeIdentityEnvironment` binds exactly the existing
Microsoft tenant and application UUIDs. It enters Preview server runtime only:
never the build environment, Production overrides or project-wide settings.
There are no passwords, client secrets, bearer tokens or new credentials in this
projection. The ordinary be6 and application source-archive paths reject a
missing pair before collecting the first Production observation or preparing a
deployment intent. This configuration check proves neither Microsoft consent
nor authentication; the actual module read must still pass. Local component
fixtures and source checks do not replace that hosted evidence.
